# 專案設定與任務表單重構設計文件

## 實作進度

| 階段 | 項目 | 狀態 |
|------|------|------|
| Phase 1 | 專案設定頁雙欄佈局 | ✅ 完成 |
| Phase 2 | 任務表單 Modal (A+B 層) | ✅ 完成 |
| Phase 3 | 任務詳情 Modal (B 層編輯) | ✅ 完成 |
| Phase 4 | 任務頁面 (建立/編輯/檢視) | ⏳ 待開發 |
| Phase 5 | 權限測試 | ⏳ 待測試 |

## 概述

重構專案設定頁面與任務表單介面，實作完整的 Kanboard API 支援，採用分層欄位設計（A 一般 / B 常用進階 / C 少用進階）。

## 欄位分層原則

| 層級 | 說明 | 出現位置 |
|------|------|----------|
| A 一般 | 最基本必要欄位 | 燈箱基本區 |
| B 常用進階 | 常用但非必要 | 燈箱展開進階區 |
| C 少用進階 | 較少使用的設定 | 僅頁面版本 |

  path: '/projects/:id/tasks/new',
  name: 'task-create',
  component: TaskCreateView

  path: '/projects/:id/tasks/:taskId',
  name: 'task-detail',
  component: TaskDetailView

## 七、測試計畫

### 7.1 測試角色矩陣

| 角色 | 說明 |
|------|------|
| app-admin | 系統管理員 |
| app-manager | 應用管理員 |
| app-user | 一般使用者 |
| project-manager | 專案管理員 |
| project-member | 專案成員 |
| project-viewer | 專案檢視者 |

### 7.2 測試情境

每個介面的每個欄位都需測試：

1. **成功情境**
   - 正確輸入後成功建立/更新
   - 選填欄位可空白

2. **失敗情境**
   - 必填欄位空白
   - 格式錯誤（如日期、數字）
   - API 錯誤處理

3. **權限情境**
   - 各角色組合的存取權限
   - 無權限時的 UI 隱藏/禁用
